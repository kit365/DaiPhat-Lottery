# Microservice Permission Registration Guide

This guide explains how your service can automatically register its permissions with the central **Account Service** (Auth Registry).

## Why Register?
By registering your permissions, they will automatically appear in the Admin Dashboard's Role Matrix, allowing admins to assign them to roles without manual SQL migrations.

## Implementation Steps

### 1. Define your Permissions Enum
Define all permissions needed by your module.

```java
public enum ArticlePermission {
    ARTICLE_VIEW("article:view", "Xem bài viết"),
    ARTICLE_CREATE("article:create", "Tạo bài viết");
    
    private final String code;
    private final String name;
    // ...
}
```

### 2. Implement the Startup Registry
Create a component that calls the Account Service during startup.

```java
@Component
@RequiredArgsConstructor
public class PermissionRegistryRunner implements CommandLineRunner {

    private final RestClient restClient; // Or WebClient/Feign

    @Override
    public void run(String... args) {
        var items = Arrays.stream(ArticlePermission.values())
            .map(p -> Map.of(
                "code", p.getCode(),
                "name", p.getName(),
                "description", "Generated by Article Service",
                "module", "ARTICLE_SERVICE"
            )).toList();

        restClient.post()
            .uri("http://account-service/api/v1/admin/roles/register")
            .body(Map.of("permissions", items))
            .retrieve()
            .toBodilessEntity();
    }
}
```

## API Specification

**Endpoint**: `POST /account/api/v1/admin/roles/register`

**Payload Structure**:
```json
{
  "permissions": [
    {
      "code": "module:action",
      "name": "Human Readable Name",
      "description": "Optional description",
      "module": "MODULE_NAME"
    }
  ]
}
```

## Part 2: Enforcement (Distributed Authorization)

Once permissions are registered, you need to enforce them in your service's APIs.

### 1. Request Enrichment (The "Pro" way)
Instead of calling the Account Service on every single request, use a `Filter` and a **Cache**.

```java
@Component
public class PermissionFilter extends OncePerRequestFilter {
    
    private final PermissionClient permissionClient;
    private final CacheManager cacheManager;

    @Override
    protected void doFilterInternal(HttpServletRequest request, ...) {
        String userId = extractUserIdFromJWT();
        
        // 1. Check local cache first (e.g. Redis/Caffeine)
        Set<String> permissions = cacheManager.get("perm:" + userId);
        
        if (permissions == null) {
            // 2. Cache miss: Call Account Service
            permissions = permissionClient.fetchPermissions(userId);
            cacheManager.put("perm:" + userId, permissions, 5, TimeUnit.MINUTES);
        }

        // 3. Populate Spring Security Authorities
        var authorities = permissions.stream()
            .map(SimpleGrantedAuthority::new)
            .toList();
            
        SecurityContextHolder.getContext().setAuthentication(
            new UsernamePasswordAuthenticationToken(userId, null, authorities)
        );
        
        filterChain.doFilter(request, response);
    }
}
```

### 2. Type-safe Checks with Enums
To "reduce load" and avoid typo mistakes, always map string codes to a local Enum.

```java
public enum LocalPermission {
    ARTICLE_VIEW("article:view"),
    // ...
}

// In your Controller
@PreAuthorize("hasAuthority(L(com.your.LocalPermission).ARTICLE_VIEW.code)")
public void view() { ... }
```

## Internal API for Reference

**Account Service Internal Endpoint**: `GET /account/api/v1/permissions/users/{userId}`

**Response**:
```json
["article:view", "user:manage", "dashboard:view"]
```

> [!TIP]
> **Performance Optimization**: Use a short-lived cache (e.g., 5 minutes) in your microservice to store these permissions. This reduces the RPS to the Account Service to a minimum while keeping permissions relatively "fresh".
